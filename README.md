# وِش الكلمة؟ — Word Battle

لعبة تخمين كلمات جماعية بين فريقين. لاعب يشرح الكلمة بدون ما يقولها، وفريقه يحاول يجيبها قبل لا يخلص الوقت.

## التشغيل

موقع ثابت (HTML + CSS + JavaScript) بدون أي أدوات بناء.

- **اللعب المحلي:** افتح `index.html` مباشرة في المتصفح، أو شغّله بإضافة **Live Server** في VS Code.
- **اللعب الجماعي:** يحتاج تشغيل الموقع من خادم (Live Server أو استضافة مثل GitHub Pages / Netlify) وليس فتح الملف مباشرة.

## هيكل المشروع

```
index.html        كل الشاشات (البداية، الإعداد، الطريقة، الدور، الكلمة، اللعب، النتيجة، الفوز، الإعدادات)
css/style.css     التصميم (Dark Mode، RTL، متجاوب)
js/config.js      بيانات ربط Supabase
js/words.js       بنك الكلمات حسب الفئات + اختيار بدون تكرار
js/store.js       حفظ الإعدادات والفرق والمباراة في المتصفح
js/sound.js       المؤثرات الصوتية (Web Audio) والاهتزاز
js/engine.js      منطق المباراة: اختيار الشارح، النقاط، الفوز
js/ui.js          عرض الشاشات والمؤقت ولوحة النقاط
js/local.js       وضع الجهاز الواحد
js/transport.js   طبقة الاتصال (Supabase Realtime أو تبويبات المتصفح للتجربة)
js/online.js      وضع الجوالات المتعددة (الغرف والمزامنة)
js/app.js         ربط الأزرار والتنقل
```

## تفعيل اللعب من الجوالات (Supabase)

1. أنشئ مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **Project Settings → API** انسخ **Project URL** و **anon public key**.
3. ضعهما في `js/config.js`:
   ```js
   WB.CONFIG = {
     SUPABASE_URL: "https://xxxx.supabase.co",
     SUPABASE_ANON_KEY: "eyJ..."
   };
   ```
4. لا تحتاج أي جداول أو SQL: اللعبة تستخدم **Realtime Broadcast + Presence** فقط. تأكد أن خيار
   *Realtime → Allow public access* مفعّل (وهو الافتراضي).

بدون هذه البيانات يشتغل **وضع التجربة**: الغرف تعمل بين تبويبات نفس المتصفح فقط، وهذا مفيد لاختبار اللعبة على جهاز واحد.

### كيف تعمل المزامنة

- جهاز المضيف هو المرجع لحالة المباراة (الأدوار، النقاط، المؤقت) ويبثها للجميع.
- **الكلمة تُختار على جهاز الشارح فقط** ولا تُرسل لأي جهاز آخر إلا بعد انتهاء الدور لعرضها في شاشة النتيجة.
- عند تحديث الصفحة يرجع اللاعب لنفس الغرفة تلقائياً، والمضيف يستعيد حالة المباراة.
- إذا انقطع اتصال لاعب، ننتظره ٢٠ ثانية. إذا كان الشارح وما رجع، الدور ينتقل لواحد من نفس فريقه تلقائياً (ما أحد يقدر يتخطى الشارح بيده).

## إضافة كلمات

أضف الكلمات في `js/words.js` داخل الفئة والمستوى المناسب (سهل/متوسط/صعب)، وارفع `BANK_VERSION` إذا عدّلت أو حذفت كلمات موجودة.

## البلاغات وصفحة الأدمن

الشارح يقدر يبلّغ عن كلمة فيها غلط (٣ بلاغات بالدور)، وتتبدّل الكلمة على طول. البلاغات توصل لجدول `word_reports` في Supabase، وتشوفها في صفحة الأدمن: `admin.html`.

### الإعداد (مرة وحدة)
1. افتح `supabase/word_reports.sql` وغيّر `ADMIN_EMAIL_HERE` لإيميلك (٣ أماكن).
2. في Supabase ← **SQL Editor** ← الصق الملف ← **Run**.
3. Supabase ← **Authentication** ← **Users** ← **Add user** ← نفس الإيميل وكلمة سر قوية.
4. Supabase ← **Authentication** ← **Sign In / Providers** ← طفّ **Allow new users to sign up**.
5. افتح `admin.html` وادخل.

### الأمان
- اللاعبين يقدرون **يضيفون** بلاغات بس؛ القراءة والتعديل لإيميل الأدمن فقط (Row Level Security).
- فحص الأمان: `bash tests/security.sh` (يضيف بلاغ تجريبي واحد اسمه «فحص أمان تلقائي»).
- اختبارات البلاغات: `node tests/reports.test.js`. معاينة اللوحة ببيانات وهمية: `tests/admin-preview.html`.
